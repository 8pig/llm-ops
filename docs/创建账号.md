# 创建账号

> 本文说明 LLMOps 如何开通账号，以及**为什么不能直接往数据库里插一条记录**。

---

## 一、账号体系

### 没有注册接口

项目**不提供注册功能**。`create_account` 在整个后端只有一处调用——`internal/service/oauth_service.py` 里 GitHub OAuth 首次登录时自动建号。

所以账号只有两个来源：

| 来源 | 说明 |
| --- | --- |
| GitHub OAuth 登录 | 首次登录自动创建账号，**默认没有密码** |
| 脚本初始化 | 用 `api/scripts/init_accounts.py` 批量创建/重置密码 |

### 两种登录方式

| 方式 | 接口 |
| --- | --- |
| 密码登录 | `POST /auth/password-login` |
| GitHub OAuth | `/auth/authorize/github` 系列 |

改密码走 `POST /account/password`，但**需要先登录**。

### 全新部署后第一次怎么登录

1. **最简单**：直接用 GitHub OAuth 登录，账号会自动创建
2. **需要密码登录**：用下面的脚本初始化一个账号

---

## 二、快速开始：用脚本批量建号

脚本位置：`api/scripts/init_accounts.py`

它会自动复用项目 `pkg/password` 的加密算法，生成合法的密码密文和盐值。

### 1. 准备账号列表

```powershell
cd D:\code\llm-ops\api
copy scripts\accounts.example.csv scripts\accounts.csv
notepad scripts\accounts.csv
```

CSV 两列，`name` 是显示名（可留空，默认取邮箱前缀）：

```csv
email,name
admin@example.com,管理员
zhangsan@example.com,张三
```

> 只放一行就是重置单个账号，放多行就是批量建号，同一个脚本都支持。

### 2. 预览（只读，不写数据库）

```powershell
.\.venv\Scripts\python.exe scripts\init_accounts.py --password Abcd1234
```

会打印账号清单并生成 `scripts/init_accounts.xlsx`。**这一步不会改动数据库**，用来核对邮箱是否正确。

### 3. 确认无误，写入数据库

```powershell
.\.venv\Scripts\python.exe scripts\init_accounts.py --password Abcd1234 --apply
```

- 邮箱**已存在** → 更新密码
- 邮箱**不存在** → 新建账号

单事务执行，全部成功才提交，中途出错自动回滚。

### 参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--csv` | `scripts/accounts.csv` | 账号列表文件 |
| `--password` | 无（则随机生成） | 统一初始密码，需符合下方密码规则 |
| `--out` | `scripts/init_accounts.xlsx` | 输出的 Excel 路径 |
| `--apply` | 关闭 | **加上才会真正写库**，不加就是预览 |
| `--db-url` | 环境变量或 `localhost:5433/llmops` | 数据库连接串 |

不指定 `--password` 时，每个账号会随机生成 12 位密码，明文写进 Excel。

### 输出的 Excel

| 列 | 说明 |
| --- | --- |
| `email` | 邮箱（登录账号） |
| `name` | 显示名 |
| `明文密码` | **敏感**，用于分发给用户 |
| `password` | 密文，写入数据库的字段 |
| `password_salt` | 盐值，写入数据库的字段 |
| `数据库操作` | 新增 / 更新 |

> Excel 含明文密码，用后请及时删除。

## 三、密码规则

由 `pkg/password/password.py` 定义：

```
^(?=.*[a-zA-Z])(?=.*\d).{8,16}$
```

即：**至少 1 个字母 + 至少 1 个数字，长度 8–16 位**。

不符合规则的密码会在参数校验层被拒，根本到不了比对那一步。脚本在 `--password` 传入不合规密码时会直接报错退出，不会写库。

## 四、手动创建（了解原理）

### 密码是怎么存的

`AccountService.update_password` 的逻辑：

```python
salt          = secrets.token_bytes(16)                              # 16 字节随机盐
password_salt = base64.b64encode(salt).decode()                      # 存库，约 24 字符
hashed        = hexlify(pbkdf2_hmac('sha256', 明文密码, salt, 10000))  # 10000 轮
password      = base64.b64encode(hashed).decode()                    # 存库，88 字符
```

关键点：**pbkdf2(10000 轮) → 转十六进制 → 再 base64**，是双重编码。

登录时 `compare_password` 反向验证：

```python
hexlify(pbkdf2_hmac('sha256', 输入密码, b64decode(盐), 10000)) == b64decode(password字段)
```

### 为什么直接 INSERT 登录不了

常见错误写法：

```sql
INSERT INTO account (name, email, password) VALUES ('Ezio', 'a@b.com', '12345678');
```

问题在于：

1. `password` 字段存的是**密文**（88 字符），不是明文
2. 缺少 `password_salt`，或盐值为空 → 用空盐算哈希，结果必然对不上
3. 密码不符合「8–16 位含字母+数字」规则时，请求在校验层就被拒

**正确做法只有两个**：用脚本生成密文，或先 OAuth 登录进去再在设置里设密码。

## 五、常见问题

### 1. 手动插了邮箱密码，登录提示「用户不存在或者密码错误」

见上一节。检查方式：

```sql
SELECT email, length(password), length(password_salt) FROM account;
```

正常的 `password` 长度应为 **88**，`password_salt` 长度应为 **24**。如果明显偏小（比如十几），说明存的是明文。

### 2. GitHub 登录的账号，用密码登录不了

OAuth 建号时 `password` 和 `password_salt` 都是空字符串，`is_password_set` 返回 `False`，密码登录会被直接拒绝。

解决：先 OAuth 登录，在账号设置里走 `POST /account/password` 设一次密码；或用脚本给该邮箱重置密码。

### 3. 邮箱已存在但想重置密码

把邮箱写进 `accounts.csv`，跑一次 `--apply` 即可，脚本会自动识别为「更新」而不是「新增」。

### 4. 脚本报找不到账号列表

```
[错误] 找不到账号列表: ...scripts\accounts.csv
```

说明还没从模板复制。执行第一步的 `copy` 命令即可。
