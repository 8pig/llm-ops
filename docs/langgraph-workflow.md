# LangGraph+Tool 实现可编排工作流运行流程

**在 LLMOPs 项目中，我们使用 LangGraph 作为后端工作流的实现基础框架，将上述分析转换成流程图后如下：**

## 架构图
```
┌─────────────────┐
│      Info       │
│  工作流基础信息  │
└────────┬────────┘
         │
┌────────▼────────┐
│     Nodes       │
│     节点信息     │
└────────┬────────┘
         │
┌────────▼────────┐
│     Edges       │
│     边信息       │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────────────┐
│            Workflow                      │
│       LangChain自定义Tool                │
│  ┌───────────────────────────────────┐  │
│  │      WorkflowState                │  │
│  │        工作流状态                  │  │
│  └───────────────────────────────────┘  │
│  ┌───────────────────────────────────┐  │
│  │          Graph                    │  │
│  │      内部Graph程序                 │  │
│  └───────────────────────────────────┘  │
│  ┌───────────────────────────────────┐  │
│  │       Nodes/Edges                 │  │
│  │   循环遍历节点与边                 │  │

        ▼                   ▼
```

## 架构逻辑说明

**在该架构中，图结构、节点、边、状态之间的类型的梳理逻辑如下：**

1. **workflow** 本身是一个 LangChain Tool 组件，在底层通过构建 **Graph图结构程序** 来完成对应的逻辑。
2. **Node节点** 本身都是 **Runnable** 可运行组件，统一实现 **invoke** 方法，并接收/返回 **workflowState** 的数据。
3. **workflowState** 中会记录 **输入数据** 以及  **每个节点产生的数据** **，并且能通过标识获取到各个节点生成的数据。**
4. **workflow** 由于存在并行节点，并且可能存在某个节点需要获取并行节点的数据，所以添加 **Edge(边)** 时，如果是并行节点，需要等待并行节点执行结束后才可以执行子节点。
5. **Graph图程序** 返回的是状态，而 **工作流** 只需要 **结束节点** 提炼的数据，所以在 **Tool组件** 内部需要对状态数据进行提取。
